# ADR 0014: RAG Security Knowledge Store and Prompt Augmentation

## Status
Accepted

## Context
AI agents and LLM triaging modules require access to domain-specific security knowledge: MITRE ATT&CK technique details, incident response playbooks, internal compliance policies, and known vulnerability analyses (Roadmap §8, §108 `AI-008`). Hardcoding this information in system prompts wastes context window space and makes playbook updates cumbersome.

## Decision
We implemented an embedded, zero-external-dependency Retrieval-Augmented Generation (RAG) knowledge engine in `server/internal/aiprovider`:

1. **Dual Search Mechanics (Hybrid Retrieval):**
   - **Vector Similarity:** Computes cosine similarity over float32 embedding vectors (`CosineSimilarity`) generated by the `ModelProvider.Embed` interface.
   - **Lexical Keyword Fallback:** Allows keyword-based title and content matching when embeddings are unavailable or offline.

2. **Structured Document Model:**
   - `KnowledgeDoc` encapsulates doc metadata, categorized by type (`mitre`, `runbook`, `cve`, `policy`).

3. **Prompt Augmentation Wrapper:**
   - `AugmentPrompt(ctx, query, topDocs)` formats retrieved knowledge sections under a structured `=== SECURITY KNOWLEDGE CONTEXT ===` block prepended to the analyst or agent query.

## Consequences

### Positive
- In-memory, fast vector retrieval in pure Go without external vector DB dependencies (milvus/pinecone/qdrant).
- Easily serialized to PostgreSQL or disk in future phases.
- Dynamically enriches LLM reasoning with real MITRE ATT&CK and runbook procedures.

### Negative
- Pure in-memory vector scanning is O(N) over indexed documents; appropriate for thousands of runbooks/MITRE docs, but will require hierarchical index (HNSW/IVF) if scaling to millions of embeddings.
